# Runbook: النقل الكامل من الإضافة → الكو-براوزر + السحب server-side (تقاعد الإضافة)

**الحالة:** مرجع حيّ للنقل. **التاريخ:** 2026-11-02. **يعتمد على:** docs/27 (باسوردلس) · docs/28 (كو-براوزر Arkose) · PR #273 (تقاعد الإضافة بالفرونت، محجوز).
**الهدف:** نقل كل شركة من **الإضافة** (ربط + سحب بيانات) إلى **الكو-براوزر** (ربط/لقط جلسة) + **السحب server-side من Fleet Hub** (أرباح/مركبات/مقاييس)، ثم **إزالة الإضافة نهائياً** — **فقط بعد إثبات الكفاءة**.

> القاعدة الذهبية سارية: كله **قراءة فقط** من أوبر (ما عدا رفض الديسباتش). الكو-براوزر = إنسان يسجّل دخوله في حسابه؛ السحب server-side = قراءة Fleet Hub بالجلسة الملتقطة، بلا كتابة الـjar.

---

## 0. أدوار الإضافة اللي نستبدلها

| دور الإضافة | البديل الجديد | الحالة |
| --- | --- | --- |
| ربط + Arkose bootstrap + لقط الجلسة | **الكو-براوزر الكامل** (docs/28 §11) | ✅ حيّ، مثبّت على tenant 15 |
| سحب الأرباح (driver metrics) | `fleet:sync-earnings` server-side | ✅ مبني، مبوّب |
| سحب المركبات | `fleet:sync-vehicles` server-side | ✅ مبني، مبوّب |
| مقاييس السائق (ساعات/قبول/إلغاء) | `fleet:sync-metrics` server-side | ✅ مبني، مبوّب |
| كرت أرباح الأسطول (roll-up) | محسوب من مجموع السائقين (تقريب) | ✅ مبني |
| Roster + live status | **الديمون** (كان server-side أصلاً) | ✅ غير متأثّر |

**أدوات التحكّم:**
- **الربط الجديد:** علم الشركة `settings.passwordless_login.cobrowse` — **toggle «ربط الكو-براوزر»** بليست الأدمن (أو tinker). يحتاج كمان: `UBER_COBROWSE_ENABLED=1` عام + الشركة **cold** (بلا جلسة) + **proxy** + `REAL_CHROME`.
- **السحب server-side:** العلم العام `UBER_SERVER_SYNC=1` + allowlist اختياري `UBER_SERVER_SYNC_TENANTS` (فاضي = كل الشركات المؤهّلة). الشركة لازم تكون مربوطة (جلسة active + supplier_cookies + proxy).

## 1. المراحل (أثبت أول، انقل بعدها)

### المرحلة ١ — إثبات الكفاءة (البوابة الحاسمة) 🔬
شغّل الجديد على **٣–٥ شركات تجريبية** **بالتوازي مع القديم** لمدّة **٣–٧ أيام**، وقارن:
- `UBER_SERVER_SYNC=1` + `UBER_SERVER_SYNC_TENANTS=<ids الشركات التجريبية>`.
- شغّل يدوياً للتسريع: `fleet:sync-earnings` · `fleet:sync-vehicles` · `fleet:sync-metrics`، وراقب لوج `fleethub.*`.
- **قارن:** عدد المركبات = Fleet Hub؟ · الأرباح server-side ≈ الإضافة؟ · **لا صفوف `driver_metrics` مكرّرة** (حدود الأسبوع)؟ · العروض ما تأثّرت؟ · الجلسة بتضل دافية + إعادة الربط تشتغل؟

**معايير النجاح (التزم فيها قبل التوسيع):**
- ربط كو-براوزر ناجح **≥ 90%** على **≥ 20** دخول حقيقي موزّعة على **≥ 3** شركات.
- أرباح/مركبات/مقاييس server-side مطابقة للإضافة ضمن هامش صغير، **بلا تكرار**.
- **صفر** انقطاع عروض · الجلسة تتجدّد تلقائياً · إعادة الربط تشتغل.

### المرحلة ٢ — نقل الربط (تدريجي، طبيعي) 🔗
- شغّل **toggle «ربط الكو-براوزر»** لكل الشركات من الأدمن.
- كل شركة لمّا جلستها تحتاج re-auth (أو شركة جديدة) → تربط **بالكو-براوزر** مش الإضافة. خلال ~شهر الكل بينتقل طبيعياً، أو أعد ربطهم استباقياً.

### المرحلة ٣ — توسيع السحب فليت-وايد 📊
- بعد نجاح المرحلة ١: **شيل** `UBER_SERVER_SYNC_TENANTS` (خليه فاضي) → السحب يشمل كل الشركات المؤهّلة.
- نافذة تحقّق متوازية فليت-وايد قصيرة → تأكّد المطابقة قبل القطع.

### المرحلة ٤ — القطع النهائي (نشيل الإضافة من اللوحة) ✂️
- **ادمج PR #273** → اللوحة تقرأ server-side بس، الكو-براوزر هو الربط الوحيد.
- بلّغ المدراء إنهم يقدروا يشيلوا/يتجاهلوا الإضافة.
- شرط الدمج: **كل الشركات النشطة** عليها `server_sync` فعّال + البيانات متحقَّقة (وإلا الشركات غير المزامَنة بتتجمّد بياناتها — التحذير على الـPR).

### المرحلة ٥ — التنظيف 🧹
- احذف الكود الميت: `frontend/src/lib/extension.ts`، `ExtensionBanner`, نصوص `connectInstallHint`/`connectInstalledHint`.
- أزل/أهمل endpoints `ext-ingest` (`POST /vehicles`, `/drivers/metrics`) بعد فترة أمان.
- `uberDataHint` نص قديم بيذكر صفحة Fleet Earnings — حدّثه.
- أكّد مقياس acceptance/cancellation rate (كسر مقابل نسبة) وبسّط `pctLabel`.
- حدّث docs/27/28 + HANDOFF + ROADMAP. أوقف نشر/صيانة الإضافة.

## 2. المخاطر + العلاج

| خطر | علاج |
| --- | --- |
| **الموت الشهري لسا بدّو نقرة بشرية** (الـOTP لصاحب الحساب) | المتبقّي الوحيد؛ **variant B** (تحويل إيميل بموافقة الشركة) يقرّبه للتلقائي، إلا وقت Arkose |
| صفوف `driver_metrics` مكرّرة (حدود أسبوع السيرفر مقابل الإضافة) | يُتحقَّق بالمرحلة ١ قبل التوسيع؛ وحّد حدود الأسبوع إذا لزم |
| truncation المركبات (`SearchVehicles` بلا صفحات) | افحص أسطول كبير مقابل Fleet Hub |
| rate limit على Fleet Hub (كل الشركات تسحب) | مبعثر أصلاً (jitter في الـjobs) + 400ms بين السائقين |
| شركة ما تزامنت + دُمج #273 | تتجمّد بياناتها (مش outage)؛ لا تدمج قبل تشغيل الأسطول |

## 3. التراجع (Rollback)
- **السحب:** أطفئ `UBER_SERVER_SYNC` → يرجع الاعتماد على الإضافة فوراً (الجداول نفسها).
- **الربط:** الإضافة تبقى مسار احتياطي حتى دمج #273؛ قبلها الكو-براوزر إضافي مش بديل قسري.
- **القطع (#273):** إذا صار مشكلة بعد الدمج، اعمل revert للـPR → ترجع اللوحة للإضافة.

## 4. مرجع سريع — الأعلام والأوامر
```bash
# السحب server-side
UBER_SERVER_SYNC=1                 # المفتاح الرئيسي
UBER_SERVER_SYNC_TENANTS=15,22     # allowlist للتحقّق (فاضي = الكل)
php artisan fleet:sync-earnings    # + sync-vehicles / sync-metrics (مجدولة 5/60/15 دقيقة)

# الربط الجديد: toggle «ربط الكو-براوزر» بالأدمن، أو:
#   settings.passwordless_login.enabled=true + .cobrowse=true  (+ cold + proxy + UBER_COBROWSE_ENABLED=1 + REAL_CHROME)
```
