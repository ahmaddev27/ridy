# خطة التنفيذ — التقاط إرساليات أوبر وتوجيهها للسائق (Ridy)

> **الحالة:** مسوّدة للمراجعة. مبنية على المكتشَف في [uber-console/](./uber-console/).
> **الستاك:** Node daemon (تيار RAMEN) + Laravel (الدماغ) + Next.js (لوحة المدير) + تطبيق موبايل لاحقاً.

---

## 0. الحقائق المؤكَّدة (أساس التصميم)

| الحقيقة | الدليل |
|---|---|
| تسجيل الدخول الآلي لأوبر **مستحيل** (MFA إجباري) | `scripts/uber-login.mjs` → `mfa_required` |
| التقاط الجلسة لازم يعمله **الإنسان** بنفسه، ونلتقط الكوكيز بعدها | same-origin يمنع القراءة من الخارج |
| تيار الإرساليات الحيّ | `vsdispatch.uber.com/ramendca/events` (RAMEN: `ack?seq=-1` ثم `recv?seq=0` SSE) |
| كل عرض يحمل `driverInfo.driverUUID` + الاسم + العنوان + الأجرة + `partnerUUID` | `uber-console/response.json` |
| `getUser` يرجّع هوية من سجّل الدخول: **uuid + firstName + lastName + email** | `uber-console/driver-me-response.json` |
| **uuid السائق = driverUUID** في العروض | تطابق البنية + رابط `supplier.uber.com/orgs/{org}/drivers/{driver}` |
| **uuid الأسطول = partnerUUID** في العروض | تطابق `7b118561...` |

**نتيجة:** الربط بالـUUID يجمع الطرفين بدون مطابقة أسماء. دخول السائق يعطينا إيميله كمان → ربط تلقائي نظيف.

## المرحلة 1 — نموذج البيانات (Laravel)

### 1.1 ربط الشركة بالأسطول
جدول `tenants` (أو `integration_connections`):
- `uber_org_uuid` — الـpartnerUUID/orgUUID تبع الأسطول (من `getUser` عند ربط المدير).

### 1.2 ربط السائق بالـUUID
جدول `drivers` (فيه `external_ids` JSON أصلاً):
- نخزّن `external_ids.uber = {driverUUID}` — المفتاح الثابت للتوجيه.
- إضافة `uber_email` nullable — للربط اليدوي/التحقّق.

### 1.3 جلسة الأسطول
جدول جديد `uber_fleet_sessions`:
- `tenant_id`, `uber_org_uuid`
- `cookies` (encrypted:array), `expires_at`
- `status` (active | expired | needs_relink), `last_event_at`

### 1.4 العروض المُلتقطة (بعد تصفية DSGVO)
جدول `dispatch_offers`:
- `tenant_id`, `driver_id` (nullable لحد ما يتربط), `driver_uuid`
- `offer_uuid` (unique — منع تكرار), `seq`
- `received_at`, `accept_window_seconds`
- **قرار خصوصية:** نخزّن الأجرة والعناوين؟ أو نرميها؟ → **يُحسم في §6**.

## المرحلة 2 — Node Daemon (الأذن)

خدمة Node منفصلة (`dispatch-daemon/`), تحت `Supervisor`/`pm2`:

1. تقرأ جلسات الأساطيل النشطة من Laravel (endpoint داخلي محمي بـtoken).
2. لكل أسطول: `ack?seq=-1` ثم تفتح `recv?seq=0` (SSE) بكوكيز الأسطول.
3. تفكّ كل حدث `push_fleet_unified_offer`.
4. **ترسل العرض الخام لـLaravel فوراً** (`POST /internal/dispatch/ingest` بـtoken) — لا منطق هنا.
5. إعادة اتصال تلقائي بالـ`seq` الأخير + backoff.
6. تكشف انقطاع الجلسة (401/403) → تبلّغ Laravel → status = `needs_relink`.

**حدود صارمة:** الـdaemon يمسك التيار ويسلّم فقط. كل المنطق في Laravel.

## المرحلة 3 — Laravel (الدماغ)

### 3.1 استقبال العرض
`POST /internal/dispatch/ingest` (محمي بـshared secret، لا Sanctum):
1. تحقّق التكرار بالـ`offer_uuid` — تجاهل المكرّر (التيار يكرّر، مؤكَّد من العينة).
2. طبّق تصفية DSGVO (§6).
3. جد السائق بالـ`driver_uuid` ← `drivers.external_ids.uber`.
4. لو انربط: خزّن + أرسل إشعار. لو لأ: خزّن كـ«غير مربوط» ليظهر للمدير.

### 3.2 التوجيه والإشعار
- ابحث عن مستخدم رايدي المربوط بالسائق → أرسل Push (FCM/APNs) بتفاصيل الرحلة.
- **واقعية النافذة 5 ثوانٍ:** الإشعار للعلم/المتابعة، لا نضمن التصرّف داخل الـ5 ثواني.

---

## المرحلة 4 — الربط (خيارين، الاثنين موجودين)

### 4.1 ربط الأسطول (تلقائي)
المدير يربط أوبر مرة → نلتقط جلسته → `getUser` → نخزّن `uber_org_uuid` + نفعّل الـdaemon.

### 4.2 ربط السائق — تلقائي
السائق يسجّل دخول أوبر من تطبيق رايدي → `getUser` → `driverUUID` + email → نربطه بحسابه فوراً. **بدون مطابقة أسماء.**

### 4.3 ربط السائق — يدوي (احتياطي، يشتغل الآن)
- نجيب roster الأسطول من `supplier.uber.com/orgs/{org}/drivers` (يُتحقَّق منه).
- المدير يشوف قائمة (اسم + email) ويطابق كل سائق بحساب رايدي بضغطة.
- يستفيد من طابور المراجعة الموجود (`ReviewQueueController::linkIdentity` — نعمّمه للسائقين).

## المرحلة 6 — قرار DSGVO (يحتاج حسمك)

تيار العروض فيه PII حسّاس: اسم الراكب، عنوان الانطلاق **والوصول**، الأجرة.

| الخيار | ماذا نخزّن | الأثر |
|---|---|---|
| **أ (متوافق)** | `{driverUUID, وقت, صار عرض}` فقط — نرمي الباقي فور الاستقبال | يحافظ على مبدأ «اكشف بدون تراقب» |
| **ب (كامل)** | كل شي (عنوان، راكب، أجرة) | يتطلّب مراجعة قانونية كاملة + مبرّر معالجة |

> **الهدف تغيّر** (كلامك) — لازم تحسم: أ أم ب؟ هذا يحدّد §1.4 و§3.1.

---

## المخاطر (مذكورة صراحة)

1. **انتهاء جلسة الأسطول** — تنقطع → المدير يعيد الربط يدوياً. نبني كشف + تنبيه.
2. **نافذة 5 ثوانٍ** — الإشعار للعلم، لا نضمن التصرّف داخلها.
3. **IP السيرفر** — أوبر قد تبطّل جلسة داتا سنتر أسرع.
4. **endpoint غير موثّق + انتحال عميل أوبر** — يخالف ToS، قد يتغيّر أي وقت. قرار تجاري مقبول منك.
